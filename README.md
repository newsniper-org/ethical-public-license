## 파일

```
NEPL-v1.ko.md    ← 정본 (한국어)
NEPL-v1.en.md    ← 번역 (영어)
NEPL-v1.ja.md    ← 번역 (일본어)
NEPL-v1.de.md    ← 번역 (독일어)

… 각 언어마다 같은 문면을 네 형식으로:
    .md   CommonMark
    .txt  UTF-8 plain text
    .rst  reStructuredText
    .typ  Typst >= 0.14

templates/  적용 고지(Application Notice) 빈 서식
tools/render.py   .md → .txt/.rst/.typ 생성기
```

**해석에 차이가 있으면 한국어본(`NEPL-v1.ko.md`)이 우선한다**(제10.1조).

형식이 넷인 이유는 편의뿐이다 — 제12.1조가 **「어떤 문서 형식으로 쓸지는 전혀 규정하지 않는다」**고 명시한다. 이 라이선스의 유일한 무조건 허용 조항이다. PDF든 HTML든 점자든 좋고, 문면만 바뀌지 않으면 된다.

## 쓰는 법

1. 라이선스 전문을 저장소에 넣는다(원하는 언어·형식으로, 몇 개든).
2. 최상위에 `LICENSE`(또는 `NOTICE`)를 두고 **적용 고지**를 채운다 — `templates/` 의 서식을 쓴다.
3. 끝. 저장소마다 달라지는 것(권리자·상위 저작물·별도 라이선스 부분·준거법·저작 부분의 상업 허용 여부)은 전부 적용 고지에 적고, 라이선스 본문은 손대지 않는다.

적용 고지에 **제5조를 완화하는 기재는 효력이 없다**(제12조).

### SPDX

표준 식별자가 없으므로 다음을 쓴다.

```
SPDX-License-Identifier: LicenseRef-NEPL-1.0
```

패키지 메타데이터(`pyproject.toml`, `package.json` 등)의 라이선스 필드에도 같은 문자열을 넣고, 파일 경로를 함께 적는다.

## 생성기

`.md` 가 정본이고 나머지 세 형식은 생성물이다. 손으로 고치지 않는다.

```sh
python3 tools/render.py          # 12개 파일을 다시 만든다
python3 tools/render.py --check  # 생성물·형식 간 문면·언어 간 구조를 한 번에 검사
just render / just check / just pdf
```

`--check` 가 보는 것은 셋이다.

1. **생성물의 최신성** — `.txt`·`.rst`·`.typ` 가 지금의 `.md` 에서 나온 것과 바이트 단위로 같은지.
2. **형식 간 문면 동일성** — 구조 표지를 걷어내고 네 형식의 본문이 글자 단위로 같은지.
3. **언어 간 구조 동일성** — 절 번호(0~12·부록), 조항 번호(63개), 각 목 기호(12개)의 **순서와 값이 네 언어에서 완전히 같은지**, 그리고 블록 수(표제·목록·예문·구분선)가 같은지. 번역본은 제10.3조가 요구하는 「이것은 번역이며 한국어본이 정본이다」 한 문단만큼만 정본보다 길 수 있다.

3번이 이 저장소에서 가장 중요한 검사다. **번역본이 정본에 없는 실체 조항을 만들어 넣는 것**(관할별 특칙을 번역에만 슬쩍 더하는 것 따위)이 제1고 법률 검토에서 치명적 결함으로 지적되었기 때문이다. 관할별 예시는 전부 **부록 A** 한 곳에 모았고, 부록 A는 네 언어에서 같은 목록이며 구속력이 없다.
